## Simple Summary

Fix a bug: when an address appears in several access list entries, warm the union of their storage keys instead of only the last entry's.

## Abstract

[EIP-2930](https://eips.ethereum.org/EIPS/eip-2930) allows the same address to appear in more than one access list entry and warms every listed storage key. Conflux charges the intrinsic gas for every entry but warms only the storage keys of the last entry of each repeated address. This CIP fixes the divergence, in both the native space and the EVM space.

## Motivation

This is an implementation bug, not an intentional design: a transaction pays for storage keys that are then left cold, so it costs more gas on Conflux than the same transaction on Ethereum. It needs a CIP only because gas consumption is consensus-critical.

## Specification

At and after the activation height, the pre-warmed storage keys of an address are the union of `storage_keys` over all access list entries carrying that address. Before it, they are the `storage_keys` of the last such entry.

Intrinsic gas is unchanged: `2400` per entry plus `1900` per storage key, counting each occurrence.

## Rationale

Matching EIP-2930 needs no further justification.

## Backwards Compatibility

Spec Breaking. A transaction whose access list repeats an address with distinct storage keys consumes less gas after the activation; nothing else about its execution changes. Access lists that list each address at most once are unaffected.

## Test Cases

`tests/berlin/eip2930_access_list/test_acl.py::test_repeated_address_acl` from the Ethereum execution spec tests, plus unit tests in the reference implementation.

## Implementation

`State::set_tx_access_list` in [conflux-rust](https://github.com/Conflux-Chain/conflux-rust).

## Security Considerations

N/A. The change only lowers the gas of an already valid transaction, for slots the sender has already paid the access list price for.
