## Simple Summary

Set upper bounds for the inputs of the ModExp precompile (0x05) and increase its gas pricing, following [EIP-7823](https://eips.ethereum.org/EIPS/eip-7823) and [EIP-7883](https://eips.ethereum.org/EIPS/eip-7883).

## Abstract

Introduce the ModExp input upper bounds defined in [EIP-7823](https://eips.ethereum.org/EIPS/eip-7823) and the ModExp gas cost increase defined in [EIP-7883](https://eips.ethereum.org/EIPS/eip-7883) as a single atomic change for both the native space and the EVM space.

## Motivation

Ethereum has activated [EIP-7823](https://eips.ethereum.org/EIPS/eip-7823) and [EIP-7883](https://eips.ethereum.org/EIPS/eip-7883) in the Fusaka hardfork. The ModExp precompile has repeatedly been a source of consensus faults and underpriced-computation DoS concerns; bounding its inputs removes pathological cases from the testing surface, and the repricing makes its cost match the actual computational resources. Supporting these changes also achieves maximum compatibility with Ethereum.

## Specification

Same as [EIP-7823](https://eips.ethereum.org/EIPS/eip-7823) and [EIP-7883](https://eips.ethereum.org/EIPS/eip-7883). In short:

* Each of the length inputs (`length_of_BASE`, `length_of_EXPONENT` and `length_of_MODULUS`) MUST be less than or equal to 8192 bits (1024 bytes). If any of them exceeds the bound, the precompile fails, returns an error, and consumes all gas (EIP-7823).
* The gas cost is computed with the EIP-7883 formula: the minimal price is raised from 200 to 500; the multiplication complexity is 16 for operands up to 32 bytes and `2 * words^2` above; the per-byte factor for the exponent part beyond 32 bytes is doubled from 8 to 16; the division by 3 of EIP-2565 is removed.

Both changes activate together at the same epoch height in both the native space and the EVM space.

## Rationale

The two EIPs modify the same precompile and were activated in the same Ethereum hardfork, so they are merged into one CIP and activated atomically.

## Backwards Compatibility

This CIP is Spec Breaking. Calls to ModExp with any length input above 1024 bytes, which succeed before the activation, will fail afterwards. According to the analysis in EIP-7823, no successful ModExp call on Ethereum mainnet between April 2018 and January 2025 used a length input above 513 bytes.
